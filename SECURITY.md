# Security Policy

## Found a Bug? 🐛

First off, thank you for taking the time to help make this project more secure! We genuinely appreciate responsible security researchers like you.

## Supported Versions

We actively maintain and patch security vulnerabilities in the following versions:

| Version | Supported          | Status |
| ------- | ------------------ | ------ |
| Latest  | ✅ | Actively maintained |
| Previous major | ✅ | Security fixes only |
| Older versions | ❌ | Please upgrade! |

**TL;DR:** Always use the latest version for the best security and features.

## Reporting a Vulnerability

**Please don't open a public GitHub issue** — that's like announcing a fire escape route to burglars.

Instead, here's what to do:

### 📧 How to Report

Send details to: **info@raimonvibe.com** (or use GitHub's private vulnerability reporting)

Include:
- A clear description of the vulnerability
- Steps to reproduce (the more detailed, the better!)
- Potential impact
- Any suggested fixes (optional, but we love collaboration!)

### ⏱️ What to Expect

- **Within 48 hours**: We'll acknowledge your report
- **Within 7 days**: Initial assessment and severity classification
- **Within 30 days**: We aim to have a fix ready (complex issues may take longer)

### 🎁 What Happens Next?

**If accepted:**
- We'll work on a fix and keep you updated on progress
- You'll get credit in our release notes (unless you prefer to remain anonymous)
- We'll coordinate disclosure timing with you
- Serious bugs might earn you a spot in our Hall of Fame!

**If declined:**
- We'll explain why we don't consider it a security issue
- We might still fix it as a regular bug
- No hard feelings — we appreciate you looking!

### 🤝 Our Commitment

- We'll treat your report confidentially
- We'll keep you informed throughout the process
- We won't take legal action against researchers who follow responsible disclosure
- We'll give credit where credit is due

## Security Best Practices for Users

- 🔄 Keep your dependencies updated
- 🔐 Never commit secrets, API keys, or passwords to the repository
- 🛡️ Use environment variables for sensitive configuration
- 📝 Review our changelog for security-related updates

## Questions?

Not sure if something is a security issue? When in doubt, reach out! We'd rather hear about something that turns out to be nothing than miss a real vulnerability.
